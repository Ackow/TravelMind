# 阶段 2 教程：不依赖 LLM 的确定性约束引擎

> 目标：亲手实现 TravelMind 的确定性约束检查能力，让程序能够回答“这个行程是否可行、具体违反了什么规则”。
>
> 本阶段不生成行程、不自动修复行程，也不接入数据库、FastAPI 业务接口、LLM、LangGraph、MCP 或真实 Provider。

## 1. 完成后应该得到什么

阶段 2 完成时，你应该拥有：

1. 与 `api-contract.md` 一致的 `ConstraintViolation` 和 `ConstraintReport`。
2. 一个统一的 `ConstraintRule` 协议。
3. 一个只包含运行时事实的 `ConstraintContext`。
4. 一个能够注册并顺序执行规则的 `ConstraintEngine`。
5. 日期、营业时间、活动重叠、交通衔接、每日结束时间、步行量、天气、预算等规则。
6. 必去地点、排除地点和每日活动数量规则。
7. `error`、`warning`、`info` 三种严重程度。
8. 每条核心规则至少一个通过用例、一个失败用例和一个边界用例。
9. 一个能够加载东京 fixture 并输出约束报告的示例脚本。
10. 相同业务输入产生相同规则结果的确定性测试。

最终执行：

```powershell

ruff format --check app tests
python -m app.scripts.check_fixture_constraints
```

脚本应该输出合法的 `ConstraintReport` JSON。报告中的 `passed` 只能由是否存在
`error` 级别违反项决定，不能由 LLM、随机数或模糊判断决定。

## 3. 本阶段要理解的核心边界

### 3.1 领域模型和规则引擎不是一回事

领域模型负责保证一个对象自身合法：

```text
Activity.end_at 必须晚于 start_at
RouteLeg.walking_meters 不能大于 distance_meters
BudgetSummary.planned_total 必须等于 items 之和
```

规则引擎负责检查多个对象组合后是否满足当前旅行要求：

```text
两个合法 Activity 组合后是否重叠
合法 Activity 是否发生在景点营业时间内
每天的合法 RouteLeg 相加后是否超过步行上限
合法 BudgetSummary 是否超过本次 TripRequest 的预算
```

不要把跨对象规则全部塞进 Pydantic `model_validator`。否则模型会依赖外部事实，难以复用和测试。

### 3.2 约束引擎只判断，不修改

规则接口应当是纯判断：

```text
Itinerary + ConstraintContext
              ↓
      ConstraintViolation[]
```

规则不得：

- 删除活动；
- 修改开始时间；
- 自动替换地点；
- 调用天气或地图 API；
- 写数据库；
- 调用 LLM；
- 随机选择修复方案。

自动修复属于阶段 3 之后的规划或重规划流程。阶段 2 只通过 `repair_hint` 提供建议。

### 3.3 缺少事实不等于规则通过

下面三种状态必须区分：

| 状态 | 示例 | 结果 |
|---|---|---|
| 明确满足 | 活动 16:00 结束，景点 17:00 闭馆 | 通过 |
| 明确违反 | 活动 18:00 结束，景点 17:00 闭馆 | `PLACE_CLOSED` |
| 无法判断 | 地点没有任何营业时间数据 | `DATA_INCOMPLETE` |

绝对不要用下面的逻辑：

```python
if not place.opening_periods:
    return []  # 错误：把未知误当成通过
```

### 3.4 什么叫确定性

相同的领域输入和相同的检查时间，应当得到：

- 相同的违反规则码；
- 相同的严重程度；
- 相同的顺序；
- 相同的 `actual` 和 `expected`；
- 相同的违反项 ID。

`checked_at` 本身会随时间变化，因此必须作为参数注入；测试中使用固定值。
违反项 ID 使用 `uuid5` 从稳定业务键生成，不使用 `uuid4()`。

## 6. 第一步：定义约束结果领域模型

创建 `backend/app/domain/constraints.py`：

```python
from datetime import date, datetime
from enum import StrEnum
from typing import Any
from uuid import UUID

from pydantic import Field, model_validator

from app.domain.common import DomainModel


class ConstraintSeverity(StrEnum):
    ERROR = "error"
    WARNING = "warning"
    INFO = "info"


class ConstraintCode(StrEnum):
    DATE_OUT_OF_RANGE = "DATE_OUT_OF_RANGE"
    ACTIVITY_OVERLAP = "ACTIVITY_OVERLAP"
    PLACE_CLOSED = "PLACE_CLOSED"
    TRANSFER_TIME_INSUFFICIENT = "TRANSFER_TIME_INSUFFICIENT"
    DAILY_END_TIME_EXCEEDED = "DAILY_END_TIME_EXCEEDED"
    MAX_WALKING_EXCEEDED = "MAX_WALKING_EXCEEDED"
    BUDGET_EXCEEDED = "BUDGET_EXCEEDED"
    WEATHER_MISMATCH = "WEATHER_MISMATCH"
    REQUIRED_PLACE_MISSING = "REQUIRED_PLACE_MISSING"
    EXCLUDED_PLACE_PRESENT = "EXCLUDED_PLACE_PRESENT"
    TOO_MANY_ACTIVITIES = "TOO_MANY_ACTIVITIES"
    DATA_INCOMPLETE = "DATA_INCOMPLETE"


class ConstraintViolation(DomainModel):
    id: UUID
    code: ConstraintCode
    severity: ConstraintSeverity
    day: date | None = None
    activity_id: UUID | None = None
    message: str = Field(min_length=1, max_length=500)
    actual: dict[str, Any] | None = None
    expected: dict[str, Any] | None = None
    repair_hint: str | None = Field(default=None, max_length=500)
    rule_version: str = Field(min_length=1, max_length=30)


class ConstraintReport(DomainModel):
    passed: bool
    violations: list[ConstraintViolation] = Field(default_factory=list)
    checked_rule_codes: list[ConstraintCode] = Field(default_factory=list)
    checked_at: datetime
    engine_version: str = Field(min_length=1, max_length=30)

    @model_validator(mode="after")
    def validate_report(self) -> "ConstraintReport":
        if self.checked_at.tzinfo is None:
            raise ValueError("checked_at must be timezone-aware")

        expected_passed = not any(
            item.severity == ConstraintSeverity.ERROR
            for item in self.violations
        )
        if self.passed != expected_passed:
            raise ValueError("passed must be true exactly when no error exists")

        violation_ids = [item.id for item in self.violations]
        if len(violation_ids) != len(set(violation_ids)):
            raise ValueError("constraint violation ids must be unique")

        if len(self.checked_rule_codes) != len(set(self.checked_rule_codes)):
            raise ValueError("checked_rule_codes must be unique")

        return self
```

### 为什么 `actual` 和 `expected` 是对象

只输出中文消息不利于程序自动修复：

```json
{
  "message": "当天步行距离超过上限"
}
```

同时提供机器字段：

```json
{
  "actual": {"walking_meters": 13500},
  "expected": {"maximum_walking_meters": 12000}
}
```

阶段 3 可以读取这些字段制定确定性的修复策略，而不需要解析中文句子。

## 7. 第二步：定义运行时上下文

创建 `backend/app/constraints/context.py`：

```python
from collections.abc import Mapping
from dataclasses import dataclass
from datetime import datetime

from app.domain.research import Place
from app.domain.trip import TripRequest


@dataclass(frozen=True, slots=True)
class ConstraintContext:
    request: TripRequest
    places_by_id: Mapping[str, Place]
    checked_at: datetime

    def __post_init__(self) -> None:
        if self.checked_at.tzinfo is None:
            raise ValueError("checked_at must be timezone-aware")
```

上下文只提供已经加载和校验过的事实。规则不能在运行中自行加载 fixture 或调用网络。

为什么使用只读 `Mapping` 和 frozen dataclass：

- 规则不能修改地点集合；
- 测试更容易发现副作用；
- 同一份上下文可以安全交给所有规则；
- 上下文不是 API 对象，无需放进 `domain`。

当前天气已经包含在 `DayPlan.weather`，路线事实已经包含在 `DayPlan.route_legs`，因此不重复放入上下文。

## 8. 第三步：定义统一规则接口

创建 `backend/app/constraints/rule.py`：

```python
from typing import Protocol

from app.constraints.context import ConstraintContext
from app.domain.constraints import ConstraintCode, ConstraintViolation
from app.domain.itinerary import Itinerary


class ConstraintRule(Protocol):
    code: ConstraintCode
    version: str

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]: ...
```

所有规则必须遵守：

1. 不修改 `itinerary` 和 `context`；
2. 不读取系统当前时间；
3. 不产生随机 ID；
4. 不依赖规则执行顺序；
5. 同一规则内输出顺序稳定；
6. 失败时返回违反项，而不是吞掉异常后假装通过。

编程错误，例如访问了不存在的属性，应当让测试失败，不要转换成 `DATA_INCOMPLETE`。

## 9. 第四步：生成稳定的违反项

创建 `backend/app/constraints/violation_factory.py`：

```python
import json
from datetime import date
from typing import Any
from uuid import UUID, uuid5

from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)


VIOLATION_NAMESPACE = UUID("f1870834-c998-4ceb-987f-96a429080001")


def make_violation(
    *,
    code: ConstraintCode,
    severity: ConstraintSeverity,
    message: str,
    rule_version: str,
    day: date | None = None,
    activity_id: UUID | None = None,
    actual: dict[str, Any] | None = None,
    expected: dict[str, Any] | None = None,
    repair_hint: str | None = None,
    discriminator: str = "",
) -> ConstraintViolation:
    fingerprint = json.dumps(
        {
            "code": code,
            "day": day.isoformat() if day else None,
            "activity_id": str(activity_id) if activity_id else None,
            "actual": actual,
            "expected": expected,
            "discriminator": discriminator,
        },
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        default=str,
    )

    return ConstraintViolation(
        id=uuid5(VIOLATION_NAMESPACE, fingerprint),
        code=code,
        severity=severity,
        day=day,
        activity_id=activity_id,
        message=message,
        actual=actual,
        expected=expected,
        repair_hint=repair_hint,
        rule_version=rule_version,
    )
```

`discriminator` 用于区分同一个活动可能产生的两个同码问题。例如交通活动前后两侧都缺少缓冲时间。

不要将 `message` 放入 ID 指纹。以后修改中文措辞不应改变违反项身份。

## 10. 第五步：实现日期范围规则

创建 `backend/app/constraints/rules/date_range.py`：

```python
from zoneinfo import ZoneInfo

from app.constraints.context import ConstraintContext
from app.constraints.violation_factory import make_violation
from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import Itinerary


class DateRangeRule:
    code = ConstraintCode.DATE_OUT_OF_RANGE
    version = "1.0.0"

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]:
        violations: list[ConstraintViolation] = []
        expected_range = context.request.date_range

        if itinerary.date_range != expected_range:
            violations.append(
                make_violation(
                    code=self.code,
                    severity=ConstraintSeverity.ERROR,
                    message="行程日期范围与旅行请求不一致",
                    actual={
                        "start_date": itinerary.date_range.start_date,
                        "end_date": itinerary.date_range.end_date,
                    },
                    expected={
                        "start_date": expected_range.start_date,
                        "end_date": expected_range.end_date,
                    },
                    repair_hint="重新按旅行请求日期生成每日计划",
                    rule_version=self.version,
                    discriminator="itinerary-range",
                )
            )

        timezone = ZoneInfo(itinerary.timezone)
        for day in itinerary.days:
            for activity in day.activities:
                local_start = activity.start_at.astimezone(timezone)
                local_end = activity.end_at.astimezone(timezone)
                if (
                    local_start.date() < expected_range.start_date
                    or local_end.date() > expected_range.end_date
                ):
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"活动“{activity.title}”超出旅行日期范围",
                            actual={
                                "start_at": local_start.isoformat(),
                                "end_at": local_end.isoformat(),
                            },
                            expected={
                                "start_date": expected_range.start_date,
                                "end_date": expected_range.end_date,
                            },
                            repair_hint="移动或删除超出旅行日期的活动",
                            rule_version=self.version,
                        )
                    )

        return violations
```

边界定义：活动发生在开始日期或结束日期当天，属于合法范围。

注意：`Itinerary` 自身已经保证 days 覆盖它自己的 `date_range`。本规则检查的是计划和用户请求之间是否一致。

## 11. 第六步：实现活动重叠规则

创建 `backend/app/constraints/rules/overlap.py`：

```python
from app.constraints.context import ConstraintContext
from app.constraints.violation_factory import make_violation
from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import Itinerary


class ActivityOverlapRule:
    code = ConstraintCode.ACTIVITY_OVERLAP
    version = "1.0.0"

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]:
        del context
        violations: list[ConstraintViolation] = []

        for day in itinerary.days:
            for previous, current in zip(
                day.activities,
                day.activities[1:],
                strict=False,
            ):
                if current.start_at < previous.end_at:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=current.id,
                            message=(
                                f"活动“{current.title}”与“{previous.title}”时间重叠"
                            ),
                            actual={
                                "previous_end_at": previous.end_at.isoformat(),
                                "current_start_at": current.start_at.isoformat(),
                            },
                            expected={"overlap_minutes": 0},
                            repair_hint="调整其中一个活动的开始或结束时间",
                            rule_version=self.version,
                            discriminator=str(previous.id),
                        )
                    )

        return violations
```

边界：

```text
前一个活动 10:00 结束，后一个活动 10:00 开始 → 不重叠
前一个活动 10:01 结束，后一个活动 10:00 开始 → 重叠
```

不要使用 `<=`，否则首尾相接的活动会被错误拒绝。

## 12. 第七步：实现营业时间规则

创建 `backend/app/constraints/rules/opening_hours.py`。

规则顺序：

1. 只检查带 `place_id` 的 `visit` 活动；
2. 从 `places_by_id` 找地点；
3. 特殊日期营业时间优先于每周常规营业时间；
4. 明确 `closed=True` 时产生 `PLACE_CLOSED`；
5. 没有对应日期的营业数据时产生 `DATA_INCOMPLETE`；
6. 活动必须完整落在开门和关门区间内。

示例核心实现：

```python
from datetime import time
from zoneinfo import ZoneInfo

from app.constraints.context import ConstraintContext
from app.constraints.violation_factory import make_violation
from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import ActivityKind, Itinerary
from app.domain.research import OpeningPeriod, Place, SpecialOpeningPeriod


OpeningValue = OpeningPeriod | SpecialOpeningPeriod


def find_opening_value(place: Place, target_date) -> OpeningValue | None:
    for period in place.special_opening_periods:
        if period.date == target_date:
            return period

    weekday = target_date.isoweekday()
    for period in place.opening_periods:
        if period.day_of_week == weekday:
            return period

    return None


def local_clock(value, timezone: ZoneInfo) -> time:
    return value.astimezone(timezone).time().replace(tzinfo=None)


class OpeningHoursRule:
    code = ConstraintCode.PLACE_CLOSED
    version = "1.0.0"

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]:
        violations: list[ConstraintViolation] = []
        timezone = ZoneInfo(itinerary.timezone)

        for day in itinerary.days:
            for activity in day.activities:
                if activity.kind != ActivityKind.VISIT or activity.place_id is None:
                    continue

                place = context.places_by_id.get(activity.place_id)
                if place is None:
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"找不到活动“{activity.title}”引用的地点事实",
                            actual={"place_id": activity.place_id},
                            expected={"place_fact_available": True},
                            repair_hint="重新加载地点详情后再检查",
                            rule_version=self.version,
                            discriminator="missing-place",
                        )
                    )
                    continue

                period = find_opening_value(place, day.date)
                if period is None:
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.WARNING,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"地点“{place.name}”缺少当天营业时间",
                            actual={"opening_period": None},
                            expected={"opening_period_available": True},
                            repair_hint="获取地点当天营业时间后再次检查",
                            rule_version=self.version,
                            discriminator="missing-opening-hours",
                        )
                    )
                    continue

                if period.closed:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"地点“{place.name}”当天闭馆",
                            actual={"closed": True},
                            expected={"closed": False},
                            repair_hint="改到开放日期或替换为其他地点",
                            rule_version=self.version,
                            discriminator="explicitly-closed",
                        )
                    )
                    continue

                start_time = local_clock(activity.start_at, timezone)
                end_time = local_clock(activity.end_at, timezone)
                assert period.open_time is not None
                assert period.close_time is not None

                if start_time < period.open_time or end_time > period.close_time:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"活动“{activity.title}”不在营业时间内",
                            actual={
                                "start_time": start_time,
                                "end_time": end_time,
                            },
                            expected={
                                "open_time": period.open_time,
                                "close_time": period.close_time,
                            },
                            repair_hint="将活动完整移动到营业时间范围内",
                            rule_version=self.version,
                            discriminator="outside-opening-hours",
                        )
                    )

        return violations
```

边界：

- 活动开始时间刚好等于开门时间：通过；
- 活动结束时间刚好等于关门时间：通过；
- 活动开始时间刚好等于关门时间，但结束更晚：失败；
- 特殊日期明确闭馆时，不再读取常规星期营业时间；
- 当前模型不支持跨午夜营业，阶段 2 不自行扩展。

## 13. 第八步：实现交通衔接规则

当前模型将交通表示为：

```text
TRANSFER Activity ──route_leg_id──> RouteLeg
```

`TransferRule` 至少检查：

1. 交通活动引用的路段存在；
2. 交通活动安排时长不短于 `RouteLeg.duration_minutes`；
3. 路线起点和终点与相邻活动地点一致；
4. 带具体出发、到达时间的路线完整落在交通活动时间内；
5. 相邻活动的总时间窗口不少于路线耗时加一份最小缓冲。

边界：实际交通时长或缓冲时间刚好等于要求时，应当通过。

活动重叠和交通不足可以同时存在。不要因为重叠规则已经报错，就跳过交通规则。

### 13.1 完整的 `TransferRule` 实现

创建 `backend/app/constraints/rules/transfer.py`：

```python
from datetime import timedelta

from app.constraints.context import ConstraintContext
from app.constraints.violation_factory import make_violation
from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import ActivityKind, Itinerary


def duration_minutes(value: timedelta) -> float:
    """保留秒级精度，避免 9 分 59 秒被截断成合法的 10 分钟。"""
    return value.total_seconds() / 60


class TransferRule:
    code = ConstraintCode.TRANSFER_TIME_INSUFFICIENT
    version = "1.0.0"

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]:
        violations: list[ConstraintViolation] = []
        buffer_limit = (
            context.request.constraints.minimum_transfer_buffer_minutes
        )

        for day in itinerary.days:
            route_legs_by_id = {
                route_leg.id: route_leg
                for route_leg in day.route_legs
            }

            for index, transfer in enumerate(day.activities):
                if transfer.kind != ActivityKind.TRANSFER:
                    continue

                route_leg_id = transfer.route_leg_id
                if route_leg_id is None:
                    # Activity 模型通常会提前拒绝这种状态；这里保留防御性检查。
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="交通活动没有引用路线事实",
                            actual={"route_leg_id": None},
                            expected={"route_leg_id_present": True},
                            repair_hint="重新查询路线并关联 RouteLeg",
                            rule_version=self.version,
                            discriminator="missing-route-leg-id",
                        )
                    )
                    continue

                route_leg = route_legs_by_id.get(route_leg_id)
                if route_leg is None:
                    # DayPlan 模型也会提前拒绝这种状态，但规则不应静默通过。
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="交通活动引用的路线事实不存在",
                            actual={"route_leg_id": str(route_leg_id)},
                            expected={"route_leg_available": True},
                            repair_hint="重新加载路线事实后再检查",
                            rule_version=self.version,
                            discriminator="missing-route-leg",
                        )
                    )
                    continue

                scheduled_minutes = duration_minutes(
                    transfer.end_at - transfer.start_at
                )
                if scheduled_minutes < route_leg.duration_minutes:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="交通活动安排的时间短于路线预计耗时",
                            actual={
                                "scheduled_minutes": scheduled_minutes,
                                "route_leg_id": str(route_leg.id),
                            },
                            expected={
                                "minimum_minutes": route_leg.duration_minutes,
                            },
                            repair_hint="延长交通活动或调整相邻活动时间",
                            rule_version=self.version,
                            discriminator="route-duration",
                        )
                    )

                if route_leg.departure_time is not None:
                    # RouteLeg 模型保证 departure/arrival 成对出现。
                    assert route_leg.arrival_time is not None
                    route_outside_transfer = (
                        route_leg.departure_time < transfer.start_at
                        or route_leg.arrival_time > transfer.end_at
                    )
                    if route_outside_transfer:
                        violations.append(
                            make_violation(
                                code=self.code,
                                severity=ConstraintSeverity.ERROR,
                                day=day.date,
                                activity_id=transfer.id,
                                message="路线实际时间没有完整落在交通活动内",
                                actual={
                                    "route_departure_time": (
                                        route_leg.departure_time.isoformat()
                                    ),
                                    "route_arrival_time": (
                                        route_leg.arrival_time.isoformat()
                                    ),
                                },
                                expected={
                                    "transfer_start_at": (
                                        transfer.start_at.isoformat()
                                    ),
                                    "transfer_end_at": (
                                        transfer.end_at.isoformat()
                                    ),
                                },
                                repair_hint="让交通活动完整覆盖路线出发和到达时间",
                                rule_version=self.version,
                                discriminator="route-time-window",
                            )
                        )

                previous = (
                    day.activities[index - 1]
                    if index > 0
                    else None
                )
                following = (
                    day.activities[index + 1]
                    if index + 1 < len(day.activities)
                    else None
                )

                if (
                    previous is not None
                    and previous.place_id is not None
                    and previous.place_id != route_leg.origin_place_id
                ):
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="路线起点与前一个活动地点不一致",
                            actual={
                                "previous_place_id": previous.place_id,
                                "route_origin_place_id": (
                                    route_leg.origin_place_id
                                ),
                            },
                            expected={"same_origin_place": True},
                            repair_hint="重新查询正确起点的路线",
                            rule_version=self.version,
                            discriminator="origin-mismatch",
                        )
                    )

                if (
                    following is not None
                    and following.place_id is not None
                    and following.place_id
                    != route_leg.destination_place_id
                ):
                    violations.append(
                        make_violation(
                            code=ConstraintCode.DATA_INCOMPLETE,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="路线终点与后一个活动地点不一致",
                            actual={
                                "following_place_id": following.place_id,
                                "route_destination_place_id": (
                                    route_leg.destination_place_id
                                ),
                            },
                            expected={"same_destination_place": True},
                            repair_hint="重新查询正确终点的路线",
                            rule_version=self.version,
                            discriminator="destination-mismatch",
                        )
                    )

                if previous is None or following is None:
                    # 位于一天开头或结尾时，没有完整的前后活动窗口可检查。
                    continue

                available_minutes = duration_minutes(
                    following.start_at - previous.end_at
                )
                required_minutes = (
                    route_leg.duration_minutes + buffer_limit
                )
                if available_minutes < required_minutes:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=transfer.id,
                            message="相邻活动之间没有预留足够的交通和缓冲时间",
                            actual={
                                "available_minutes": available_minutes,
                                "route_minutes": route_leg.duration_minutes,
                                "buffer_minutes": (
                                    available_minutes
                                    - route_leg.duration_minutes
                                ),
                            },
                            expected={
                                "minimum_available_minutes": (
                                    required_minutes
                                ),
                                "minimum_buffer_minutes": buffer_limit,
                            },
                            repair_hint="拉开相邻活动时间或选择更快的交通方式",
                            rule_version=self.version,
                            discriminator="activity-window",
                        )
                    )

        return violations
```

这里将 `minimum_transfer_buffer_minutes` 解释为相邻两个非交通活动之间，
除路线耗时外总共还要保留的一份缓冲时间：

```text
后一个活动开始 - 前一个活动结束
>= RouteLeg.duration_minutes + minimum_transfer_buffer_minutes
```

缓冲可以分布在交通活动之前、交通活动内部的候车时间或交通活动之后，
不会错误地要求前后各保留一整份缓冲。

## 14. 第九步：实现每日结束时间规则

创建 `daily_end_time.py`：

```python
from datetime import time
from zoneinfo import ZoneInfo

from app.constraints.context import ConstraintContext
from app.constraints.violation_factory import make_violation
from app.domain.constraints import (
    ConstraintCode,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import Itinerary


class DailyEndTimeRule:
    code = ConstraintCode.DAILY_END_TIME_EXCEEDED
    version = "1.0.0"

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
    ) -> list[ConstraintViolation]:
        violations: list[ConstraintViolation] = []
        limit = time.fromisoformat(
            context.request.constraints.daily_end_time
        )
        timezone = ZoneInfo(itinerary.timezone)

        for day in itinerary.days:
            for activity in day.activities:
                local_end = (
                    activity.end_at.astimezone(timezone)
                    .time()
                    .replace(tzinfo=None)
                )
                if local_end > limit:
                    violations.append(
                        make_violation(
                            code=self.code,
                            severity=ConstraintSeverity.ERROR,
                            day=day.date,
                            activity_id=activity.id,
                            message=f"活动“{activity.title}”超过每日最晚结束时间",
                            actual={"end_time": local_end},
                            expected={"latest_end_time": limit},
                            repair_hint="缩短活动或将其移动到更早时间",
                            rule_version=self.version,
                        )
                    )

        return violations
```

边界：结束时间恰好等于 `daily_end_time` 时通过。

## 15. 第十步：实现每日最大步行量规则

不要只相信 `DayStatistics.walking_meters`，它可能是旧缓存。规则应从当天 `RouteLeg` 重新求和：

```python
actual_walking = sum(
    route_leg.walking_meters
```

规则行为：

## 16. 第十一步：实现天气兼容规则

阶段 2 使用明确策略，不让 LLM 判断：

| 天气适宜度 | 活动属性 | 严重程度 |
|---|---|---|
| `poor` | `outdoor` | error |
| `poor` | `mixed` | warning |
| `poor` | `indoor` | 通过 |
| `acceptable` | 任意 | 通过 |
| `good` | 任意 | 通过 |
| 无天气数据 | 需要判断的 visit | `DATA_INCOMPLETE/warning` |

只检查 `visit` 和明确需要户外条件的活动。不要对 `transfer`、`check_in` 等活动盲目产生天气冲突。

核心实现：

```python
if day.weather is None:
    # DATA_INCOMPLETE warning
    continue

if day.weather.outdoor_suitability == "poor":
    if activity.indoor_outdoor == "outdoor":
        severity = ConstraintSeverity.ERROR
    elif activity.indoor_outdoor == "mixed":
        severity = ConstraintSeverity.WARNING
    else:
        continue

    violations.append(
        make_violation(
            code=ConstraintCode.WEATHER_MISMATCH,
            severity=severity,
            day=day.date,
            activity_id=activity.id,
            message=f"活动“{activity.title}”与当天恶劣天气不兼容",
            actual={
                "outdoor_suitability": day.weather.outdoor_suitability,
                "activity_type": activity.indoor_outdoor,
            },
            expected={"preferred_activity_type": "indoor"},
            repair_hint="替换为室内地点或移动到天气较好的日期",
            rule_version=self.version,
        )
    )
```

东京 fixture 中 2026-10-02 是 `poor`，可以用浅草寺构造明确冲突，用东京国立博物馆构造通过用例。

## 17. 第十二步：实现预算规则

### 17.1 总预算

使用经过换算后的 `itinerary.budget.planned_total` 和请求预算比较：

```python
actual = itinerary.budget.planned_total
limit = context.request.constraints.total_budget
```

先检查币种：

- 币种不同：不能直接比较，产生 `DATA_INCOMPLETE/error`；
- 币种相同且未超限：通过；
- 超限且 `budget_is_hard_limit=True`：`BUDGET_EXCEEDED/error`；
- 超限但不是硬限制：`BUDGET_EXCEEDED/warning`。

边界：刚好花完预算时通过，`remaining_amount=0` 不是超限。

### 17.2 每日费用一致性

当前 `TripConstraints` 没有“每日预算上限”字段，不要擅自创造平均每日硬上限。

本阶段的“每日预算检查”指验证每日统计和预算明细一致：

```python
expected_daily_amount = sum(
    item.amount.amount
    for item in itinerary.budget.items
    if item.date == day.date
)
actual_daily_amount = day.statistics.estimated_cost.amount
```

不一致时产生 `DATA_INCOMPLETE/warning`，提示重新计算统计。

这一区分很重要：

```text
用户没有设置每日上限 ≠ 每日上限等于总预算除以天数
```

## 18. 第十三步：实现地点选择与活动数量规则

API 契约还定义了：

- `REQUIRED_PLACE_MISSING`；
- `EXCLUDED_PLACE_PRESENT`；
- `TOO_MANY_ACTIVITIES`。

### 18.1 必去与排除地点

阶段 1 的请求仍然使用地点名称，计划使用 Place ID，因此需要通过 `places_by_id` 解析：

```python
visited_names: set[str] = set()

for day in itinerary.days:
    for activity in day.activities:
        if activity.place_id is None:
            continue
        place = context.places_by_id.get(activity.place_id)
        if place is None:
            continue
        visited_names.add(place.name.casefold())
        if place.localized_name:
            visited_names.add(place.localized_name.casefold())
```

规则：

- 必去名称不在集合中：`REQUIRED_PLACE_MISSING/error`；
- 排除名称出现在集合中：`EXCLUDED_PLACE_PRESENT/error`；
- Activity 引用了不存在的 Place ID：`DATA_INCOMPLETE/error`。

不要使用模糊字符串相似度。名称归一化只做阶段 1 已约定的去除首尾空格和 `casefold()`。

### 18.2 每日最大活动数

明确计数策略：

```python
counted_kinds = {
    ActivityKind.VISIT,
    ActivityKind.MEAL,
    ActivityKind.REST,
    ActivityKind.FREE_TIME,
}
```

交通、入住和退房是结构性活动，不计入用户设置的游玩活动上限。


## 19. 第十四步：实现 ConstraintEngine

创建 `backend/app/constraints/engine.py`：

```python
from collections.abc import Iterable, Sequence

from app.constraints.context import ConstraintContext
from app.constraints.rule import ConstraintRule
from app.domain.constraints import (
    ConstraintCode,
    ConstraintReport,
    ConstraintSeverity,
    ConstraintViolation,
)
from app.domain.itinerary import Itinerary


ENGINE_VERSION = "1.0.0"

SEVERITY_ORDER = {
    ConstraintSeverity.ERROR: 0,
    ConstraintSeverity.WARNING: 1,
    ConstraintSeverity.INFO: 2,
}


def violation_sort_key(item: ConstraintViolation) -> tuple:
    return (
        SEVERITY_ORDER[item.severity],
        item.day.isoformat() if item.day else "",
        item.code.value,
        str(item.activity_id or ""),
        str(item.id),
    )


class ConstraintEngine:
    def __init__(self, rules: Sequence[ConstraintRule]) -> None:
        codes = [rule.code for rule in rules]
        if len(codes) != len(set(codes)):
            raise ValueError("constraint rule codes must be unique")
        self._rules = tuple(rules)

    def check(
        self,
        itinerary: Itinerary,
        context: ConstraintContext,
        rule_codes: Iterable[ConstraintCode] | None = None,
    ) -> ConstraintReport:
        selected_codes = set(rule_codes) if rule_codes is not None else None
        selected_rules = [
            rule
            for rule in self._rules
            if selected_codes is None or rule.code in selected_codes
        ]

        violations = [
            violation
            for rule in selected_rules
            for violation in rule.check(itinerary, context)
        ]
        violations.sort(key=violation_sort_key)

        checked_rule_codes = sorted(
            {rule.code for rule in selected_rules},
            key=lambda code: code.value,
        )
        passed = not any(
            item.severity == ConstraintSeverity.ERROR
            for item in violations
        )

        return ConstraintReport(
            passed=passed,
            violations=violations,
            checked_rule_codes=checked_rule_codes,
            checked_at=context.checked_at,
            engine_version=ENGINE_VERSION,
        )
```

### 默认规则注册表

可以在 `engine.py` 或 `constraints/__init__.py` 提供：

```python
def create_default_engine() -> ConstraintEngine:
    return ConstraintEngine(
        rules=(
            DateRangeRule(),
            ActivityOverlapRule(),
            OpeningHoursRule(),
            TransferRule(),
            DailyEndTimeRule(),
            WalkingLimitRule(),
            WeatherCompatibilityRule(),
            BudgetRule(),
            RequiredPlaceRule(),
            ExcludedPlaceRule(),
            ActivityCountRule(),
        )
    )
```

如果一个实现会产生多个契约规则码，例如地点选择同时处理“必去”和“排除”，应拆成两个规则类，保证 `rule.code` 唯一且筛选语义清楚。

### 未知筛选规则码

当前 Python 方法接收 `ConstraintCode`，非法字符串会在调用前被 Pydantic/API 层拒绝。

未来 API 接收空 `rule_codes` 时，契约规定表示执行所有规则。实现 API 适配层时应将空列表转换为 `None`，不要让引擎返回“没有检查任何规则”。

## 25. 错误、警告和信息的建议口径

### error

计划不能被宣布为可行：

- 活动重叠；
- 明确闭馆；
- 交通时间不足；
- 超过硬预算；
- 超过硬步行上限；
- 必去地点缺失；
- 排除地点出现；
- 缺少用于结构性校验的地点事实。

### warning

计划仍可展示，但需要用户注意或补充事实：

- mixed 活动遇到恶劣天气；
- 缺少营业时间；
- 预算不是硬限制但已经超出；
- 缓存统计与重新计算结果不一致；
- 缺少非关键天气信息。

### info

不影响可行性，仅作为解释：

- 当天活动数量接近上限；
- 预算剩余低于某个提示阈值；
- 使用了估算路线数据。

阶段 2 不必为了使用 `info` 而创造无价值提示。没有合理场景时可以不产生 info。

## 30. 常见错误

### 30.1 在规则中使用 `datetime.now()`

结果会随运行时间改变。使用 `context.checked_at`。

### 30.2 使用 `uuid4()` 创建违反项 ID

相同输入报告不相等，前端也无法稳定追踪同一个问题。使用 `uuid5()` 和稳定业务指纹。

### 30.3 把无营业时间当作全天营业

这是把未知事实当成已验证事实。返回 `DATA_INCOMPLETE`。

### 30.4 用字符串直接比较不同时区时间

先使用 `ZoneInfo(itinerary.timezone)` 转换成目的地本地时间，再比较。

### 30.5 使用 `model_copy(update=...)` 制造非法测试对象

它可能跳过校验。使用 dict 修改后重新 `model_validate()`。

### 30.6 依赖测试中的违反项数量

添加新规则会让总数增加。优先断言规则码集合、严重程度和关键字段。

### 30.7 规则自动修改行程

判断与修复混合后，规则顺序会影响结果，也很难解释。阶段 2 只返回报告。

### 30.8 平均分配总预算作为每日硬上限

用户没有提供每日上限时，不要创造新约束。只检查每日统计一致性和总预算。

### 30.9 只测试失败，不测试边界

最常见业务错误是 `<` 和 `<=` 写反。每条数值或时间规则都必须测试“刚好等于”。
